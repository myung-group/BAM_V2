# racev2_torch: PyTorch inference port of RACEv2

`racev2_torch` re-implements the RACEv2 interatomic potential of this repository in plain PyTorch, for inference
only. The original is `bam_omat24/race_nnx.py`, class `RACE`, written in JAX + Flax NNX + e3nn-jax. The port includes
a converter that loads the trained JAX parameters without JAX, and an ASE calculator. Use it to distribute trained
models to people who do not use JAX, and as the basis for MD coupling (ML-IAP).

- Float64 throughout.
- Features use e3nn-jax's `mul_ir` layout. Every JAX weight has a torch parameter with the same path and shape:
  `layers/3/linear_2/weight_w_0_0_512x0e_128x0e` in JAX is `layers.3.linear_2.weight_w_0_0_512x0e_128x0e` in torch.
- No e3nn dependency. Spherical harmonics, Clebsch–Gordan tensors, the cue edge tensor product and the normalised
  activations are re-implemented in `racev2_torch/o3.py` and `racev2_torch/model.py`. e3nn-torch is used only in
  `tests/selfcheck.py`.
- The forward pass keeps the JAX split, so that a domain-decomposed MD driver can exchange node features after
  every layer:
  - `prelude`: edge features, embedding, UFF stratum, atomic basis
  - `layer_step`: one layer and its energy stratum
  - `finalize`: sum of strata, scale and shift

## Files

| file | content |
|---|---|
| `racev2_torch/model.py` | `RACEv2` module, `resolve_config` (config → hyper-parameters, same as `train_3bpa.build_model`) |
| `racev2_torch/o3.py` | irreps, Clebsch–Gordan tensors (verbatim numpy port of e3nn-jax `su2.py`/`so3.py`), spherical harmonics (e3nn-jax recursive algorithm), normalised-activation constants |
| `racev2_torch/convert.py` | JAX checkpoint (pickle, read without JAX) or `params.npz` + `config.json` → model file |
| `racev2_torch/calculator.py` | ASE calculator (energy, free_energy, forces, stress, per-atom energies) |
| `racev2_torch/constants.py`, `data/element_tables.json` | UFF vdW constants, covalent radii, valence-shell radii (generated by `tools/make_element_tables.py` from `race_nnx.py`, `train_3bpa.py`, `atomic_shells.json`) |
| `tests/compare_reference.py` | layer-by-layer comparison with a JAX reference dump (`tools/dump_jax_reference.py`) |
| `tests/selfcheck.py` | checks that need no JAX: CG and SH against e3nn-torch, invariance and equivariance, finite differences |
| `tools/tpy` | Python of the KISTI PyTorch container + venv (torch 2.7, ase, e3nn 0.6) |

## Usage

```bash
# convert (no JAX needed); default entry ema_params, as bam_omat24/predict.py
racev2_torch/tools/tpy -m racev2_torch.convert --ckpt runs/<run>/ckpt_<run>.pkl --out model.pt
# or from a reference dump
racev2_torch/tools/tpy -m racev2_torch.convert --npz ref/params.npz --config ref/config.json --out model.pt
```

```python
from racev2_torch import RACEv2
from racev2_torch.calculator import RACEv2Calculator
atoms.calc = RACEv2Calculator('model.pt')            # device='cuda' possible (untested, see below)
atoms.get_potential_energy(), atoms.get_forces(), atoms.get_stress()
```

**Calculator energies.** Calculator energies are **total** energies: the model output plus Σ E0 (`atom_energies`
of the config).
- By default the E0 values are added in float64, as `bam_omat24/predict.py:155` does.
- `e0='float32'` adds float32-rounded E0 instead, as `utils.energy_forces_stress` does with `l_train=False`
  (`race_nnx.py:2202`). The two differ by ≤ ~4e-7 eV per atom.
- The JAX models built by `train_3bpa.build_model` always have `l_train=True` (`train_3bpa.py:601`). So the model
  energy itself never contains E0, in JAX or here.

**Geometry rounding.** `jax_compat=True` rounds positions, cell and volume to float32 before the evaluation, as
`data_3bpa.preprocess_graph` (`data_3bpa.py:68,84-86`) does for every JAX prediction. Use it only to reproduce JAX
numbers bit for bit. The default evaluates the float64 geometry as given.

**Model API.** `RACEv2.forward(positions, species, senders, receivers, shifts=Sij, cell, n_node, n_edge, cutoff, volume, node_mask)` returns:
- `energy`: per graph, without E0
- `forces`
- `stress`: Voigt xx yy zz yz xz xy, eV/Å³, (1/V) dE/dε, the same sign as ASE
- `node_energies`
- `strata`

**Per-layer use (ML-IAP).** Call these in order:
- `edge_vectors`, or pass edge vectors directly
- `prelude(species, senders, receivers, r_feat, r_dist)`
- `layer_step(ctx, i, h, h_prev)` for each layer, with the Chebyshev history `h_prev` = input of layer i−1 for i ≥ 2
- `finalize(ctx, h)`

`RACEv2.run_layers` is the reference loop.

**Memory.** `model.edge_chunk = K` evaluates the edge tensor product in chunks of K edges and recomputes them in the
backward pass. The plain-torch edge TP materialises the per-edge messages: E × 12,736 doubles per layer for
128 channels.

**Graph convention.** The graphs follow `data_3bpa.preprocess_graph` and `neighbors.py`:
- receiver = i, sender = j, `Sij = −S` (ASE shift S)
- the edge vector is r = x_j − (x_i + Sij·cell)

The calculator builds its graph with `ase.neighborlist.neighbor_list('ijS')`, the default backend of the training
graphs.

**Supported options.** Only the option family of the MPtrj configs is implemented, and `resolve_config` raises
`NotImplementedError` for anything else:
- x_mode basis, x_norm hill
- residual chebyshev, update linear, message_norm avg, readout_mode gated
- x/f readouts on, layer_scale
- radial_prior, radial_shells, pair_repulsion uff (with switch)
- species_rank (with or without prune), periodic or not

Not converted:
- the variance heads: `frc_logvar`, `energy_logvar`, `stress_logvar`
- `x_linear`, which is unused with x_mode basis
- DeNS and the noise heads, which are refused

## Validation status (2026-11-13, CPU, login node, single thread)

### Against the JAX reference dumps

`tests/compare_reference.py <ref_dir>` was run on both dumps:
- `ref_hub001_e40`: `mptrj_L5x128_hub001_s42`, full element tables
- `ref_sr32_e10`: `mptrj_L5x128_hub001_sr32_s42`, species_rank 32 + prune

Each dump has 12 periodic MPtrj validation structures of 3–88 atoms and 64–3,436 edges. The torch model ran on the
exact padded graphs of the dump. The table gives the max abs difference over all frames, with real nodes, edges and
graphs only:

| quantity | hub001_e40 | sr32_e10 |
|---|---|---|
| normalised silu / tanh / sigmoid, CG (all l ≤ 3), SH, x-product example | ≤ 1.8e-15 | ≤ 1.8e-15 |
| static tables (shell radii, covalent radii, E0, radial prior scales, tp_irreps per layer) | identical | identical |
| prelude: radial basis, SH, r, shell envelopes, atomic basis, UFF stratum | ≤ 8.9e-15 | ≤ 3.3e-15 |
| layer features in / x / out (all 5 layers) | ≤ 1.8e-12 (rel ~1e-14) | ≤ 4.6e-13 |
| strata and parts (node / x / f) | ≤ 2.2e-14 | ≤ 2.1e-14 |
| node energies | 3.1e-15 | 3.6e-15 |
| energy (eV, without E0) | 2.8e-14 | 2.8e-14 |
| forces (eV/Å) | 1.3e-14 | 1.5e-14 |
| stress (eV/Å³) | 5.4e-16 | 3.5e-16 |
| ASE calculator: own neighbour list, `jax_compat`, total energy with float64 E0 | E 1.1e-13, F 1.3e-14, S 5.4e-16 | E 1.1e-13, F 1.5e-14, S 3.5e-16 |

- The edge counts of the calculator's neighbour list equal the JAX graphs in all 12 frames.
- `frames.extxyz` does not hold the exact float32 positions of the graphs: they differ by up to 9.5e-7 Å after
  rounding. The calculator check therefore uses the graph positions and the extxyz cell; the cell does round to the
  graph cell exactly. With the extxyz positions, differences are about 1e-5 eV/Å, which is the effect of the input
  change, not of the model.
- `compare_reference.py` uses `edge_chunk=1024`, so the chunked path is checked on the frames with more than 1,024
  edges, and the unchunked path on the others.

### Self-checks

`tests/selfcheck.py --model <converted sr32_e10 model>`:
- **CG and SH against e3nn-torch.** CG agree to 1.7e-16, SH to 2.4e-15. SH are equivariant to 2e-14.
- **Normalised silu constant.** The grid constant is c_silu = 0.5964586854233042. JAX uses this grid value, which is
  1.8e-5 away from the exact Gaussian integral: a random-sample or quadrature constant would not reproduce JAX.
- **Rotation, translation and permutation.** These checks used a 4-atom sheared MgO cell. The energy changes by
  ≤ 4e-15, forces and stress transform correctly to 1e-14.
- **Finite differences.** Forces agree to 2e-7 and stress to 5e-8, which is the O(h²) truncation at h = 1e-4.
- **Other checks.** The 2×1×1 supercell is extensive (difference 0). A CH₂O molecule (no pbc) is invariant, and its
  forces sum to zero. Chunked and unchunked edge evaluation agree to 9e-16.

All three target configs build. Parameter counts without the skipped heads and x_linear:

| config | parameters |
|---|---|
| L5x128 | 44.41 M |
| L5x128 sr32 | 17.74 M |
| L5x64 sr32 | 4.72 M |

### Not verified yet

- **hidden 64 config (`mptrj_L5x64_hub001_sr32_s42`).** There is no JAX reference dump for it. A pickled checkpoint
  of this shape (`mptrj_L5x64_sr32_smoke`) converts with every name and shape matched (219 arrays) and passes
  `selfcheck.py`. Only the channel count differs from the validated configs.
- **Pickle converter path.** It was not compared numerically to a dump of the same weights. It maps every parameter
  of the L5x64 smoke checkpoint (all names and shapes match), and its key handling is the same as the `params.npz`
  path, which is validated.
- **Not run at all:**
  - GPU / CUDA
  - float32 inference
  - batches with more than one real graph (the dumps have one real graph plus the padding graph)
  - molecules (non-periodic) against JAX
  - the ML-IAP / LAMMPS coupling, which is not written
- **Speed.** The plain-torch edge TP is not optimised. A cuequivariance-torch kernel would be the fast path for MD.
